# User Shuffle — ให้ผู้ใช้สับ ตัด และจั่วไพ่เอง

หลักการ: **ผู้ใช้ต้องควบคุมการสับ ตัด และจั่วได้อิสระทุกขั้น** agent ทำหน้าที่ดูแลพิธีและเป็นคนอ่าน ไม่ใช่คนเลือกไพ่ให้

ถามผู้ใช้ตั้งแต่ต้นว่าจะใช้โหมดไหน ถ้าผู้ใช้ไม่เลือก ให้ใช้ตามลำดับนี้: H (ถ้าแสดง/ส่งหน้าเว็บได้) → B (ถ้ารันโค้ดได้) → C

> "อยากจับไพ่แบบไหนคะ 🃏
> (H) เปิดโต๊ะไพ่บนหน้าเว็บ — สับ ตัด จั่ว และพลิกไพ่ด้วยมือคุณเอง แล้วส่งผลกลับมา
> (A) มีไพ่จริง สับและจับเอง แล้วบอกผลมา
> (B) สับไพ่เสมือนจริงในแชท — คุณเลือกวิธีสับ จำนวนรอบ จุดตัด และใบที่จะจั่วเองทั้งหมด
> (C) เลือกเลข 1–78 ตามใจ
> (D) ให้สุ่มให้เลย ไม่ต้องทำพิธี"

---

## โหมด H — โต๊ะไพ่ HTML (`assets/tarot-table.html`)

หน้าเว็บไฟล์เดียว ไม่ต้องติดตั้งอะไร ใช้ `crypto.getRandomValues` ในเบราว์เซอร์ของผู้ใช้ **agent จึงไม่เห็นลำดับไพ่เลย** จนกว่าผู้ใช้จะส่งผลกลับมา

ดีไซน์สไตล์คอมิก + กระดาษ (ฟอนต์ Mali, ไอคอน Phosphor แบบฝัง SVG ในไฟล์, รองรับ dark mode และจอมือถือ) สิ่งเดียวที่โหลดจากอินเทอร์เน็ตคือฟอนต์จาก Google Fonts ถ้าออฟไลน์ หน้ายังใช้งานได้ครบ แต่จะใช้ฟอนต์ระบบแทน

### สิ่งที่ผู้ใช้ทำได้ในหน้า
1. **เลือกหมวด:** 8 หมวด (ถามสั้น ความรัก ตัดสินใจ เจาะเรื่อง อ่านละเอียด ช่วงเวลา จิตวิญญาณ กำหนดเอง)
1. **เลือกแบบไพ่:** การ์ดของแต่ละสเปรดในหมวดนั้น บอกจำนวนใบ ใช้ดูอะไร และตำแหน่งแรก ๆ (หมวดกำหนดเองให้เลือก 1 ถึง 20 ใบ)
1. **ตั้งจิต:** เห็นตำแหน่งทั้งหมดของสเปรดที่เลือก พิมพ์คำถาม เปิด/ปิดไพ่กลับหัว หรือกดเปลี่ยนแบบ
2. **สับ:** Riffle · Overhand · Wash (ทำให้ไพ่กลับหัวได้) · Pile (เลือก 2–7 กอง) กี่ครั้งก็ได้ หรือ **กดค้าง** เพื่อสับต่อเนื่องแล้วปล่อยเมื่อพอ — มีโอกาสไพ่กระเด็น (jumper) ให้เลือกเก็บไว้อ่านหรือใส่คืน
3. **ตัด:** 1–5 กอง เลื่อนจุดตัดเอง แตะกองตามลำดับที่จะวางกลับ หมุนกองกลับหัวได้ ตัดซ้ำได้ หรือข้ามได้
4. **จั่ว:** แผ่ไพ่คว่ำ 78 ใบ แตะเลือกตามจำนวนตำแหน่ง (ยกเลิกใบล่าสุดได้ก่อนยืนยัน) หรือจั่วจากบนสุด
5. **เปิดไพ่:** แตะพลิกทีละใบ ดูไพ่ก้นสำรับ หรือจั่วไพ่ขยายความเพิ่ม
6. **ผลลัพธ์:** ปุ่มคัดลอกข้อความสรุป → วางกลับในแชท

### ไร้รอยต่อ: ส่งผลกลับเองอัตโนมัติ (`scripts/table_server.py`) ⭐
ใช้เมื่อ agent รันคำสั่งได้ เป็นวิธีที่แนะนำที่สุด
```bash
python3 scripts/table_server.py --q "แนวโน้มความรัก 3 เดือน" --spread relationship --ctx "สถานะ: คุย ๆ กันอยู่ · คุยกันมา 2 เดือน"
```
- เซิร์ฟเวอร์ผูกกับ 127.0.0.1 เท่านั้น สุ่มพอร์ตว่าง และใส่ token สุ่มใน URL (`ret=`) หน้าเว็บต้องส่ง token กลับมาพร้อมผล
- เปิดเบราว์เซอร์ให้อัตโนมัติ (`--no-open` เพื่อแค่พิมพ์ URL ลง stderr แล้วให้ agent เปิดใน browser pane ของตัวเอง)
- เมื่อผู้ใช้กด "ส่งผลกลับไปที่แชท" ในหน้าเปิดไพ่ หน้าเว็บ POST ผลไปที่ `/result` แล้วหน้าแสดงว่า "ส่งผลกลับไปที่แชทแล้ว"
- สคริปต์พิมพ์ข้อความผลการจั่วลง stdout แล้วจบ (exit 0) — `--json` เพื่อได้ `{text, data}` แบบมีโครงสร้าง · exit 2 = หมดเวลา (`--timeout` ค่าเริ่มต้น 900 วินาที)
- รันแบบ background แล้วรอการแจ้งเตือนว่าจบ จากนั้นแปลผลทันทีตาม "แปลผลอัตโนมัติ" ใน SKILL.md
- ถ้าผู้ใช้จั่วไพ่ขยายความหลังส่งไปแล้ว หน้าเว็บจะบอกให้คัดลอกผลชุดใหม่มาวางเอง

### ส่งให้ Claude Code อ่านจากลิงก์ claude.ai (capability `comments`)
ถ้า Artifact ประกาศ `comments: {}` และมี Claude session เฝ้าดู artifact อยู่ (เช่น Claude Code ที่เผยแพร่หน้านี้) ปุ่มสุดท้ายในหน้าเปิดไพ่จะเป็น "ส่งให้ Claude อ่านไพ่"
- กดแล้วหน้าเว็บเรียก `canSendToClaude()` (ต้องเป็น `"available"`) → `anchorFor(panel)` → `sendToClaude({anchor, text})` จากการกดของผู้ใช้โดยตรง
- `text` = "อ่านไพ่ชุดนี้ให้หน่อย (ใช้ skill tarot-reading แปลผลอัตโนมัติ)" + ข้อความผลการจั่ว ตัดให้ไม่เกิน 3,900 ไบต์ (ย่อบรรทัดพิธีก่อนถ้ายาว)
- ครั้งแรกระบบจะถามผู้ใช้ให้อนุญาตคอมเมนต์ · ส่งสำเร็จ: หน้าแสดง "ส่งให้ Claude แล้ว กำลังรอคำทำนาย"
- **คำทำนายขึ้นในหน้าเอง (capability `db`):** หน้าสร้างรหัส `readings/<id>` ใส่ไว้ในคอมเมนต์ แล้วฟังเอกสารนั้นด้วย `onSnapshot` — `status: "reading"` → "Claude ได้รับไพ่แล้ว กำลังอ่านให้อยู่" · มี `text` → แสดงคำทำนาย (Markdown แบบง่าย) ทันที · รอเกิน 3 นาทีจะแนะนำให้ดูในคอมเมนต์ของหน้า
- เหตุผลที่ต้องใช้ db: capability `comments` เขียนได้อย่างเดียว หน้าเว็บอ่านคำตอบในเธรดคอมเมนต์ไม่ได้ คำตอบในเธรดจึงเห็นได้เฉพาะในแผงคอมเมนต์ของ claude.ai
- ส่งไม่ได้ (`claude_unavailable`, `forbidden` ฯลฯ): หน้าบอกเหตุผลเป็นภาษาไทย และมีปุ่ม "อ่านคำทำนายในหน้านี้แทน" · `consent_required` หรือ `rate_limited`: มีปุ่ม "ส่งอีกครั้ง"
- ฝั่ง agent: เมื่อได้รับคอมเมนต์นี้ ให้แปลผลทันทีแล้วตอบในเธรดเดิม ไม่ต้องถามอะไรก่อน

### อ่านคำทำนายในหน้าเว็บ (เมื่อเปิดเป็น Claude Artifact)
ถ้าหน้าเว็บเผยแพร่เป็น Artifact ที่ประกาศ capability `sample` ปุ่มสุดท้ายจะเป็น "ดูคำทำนาย" และหน้าจะขอให้ Claude อ่านไพ่ให้ทันทีในหน้า (สตรีมทีละส่วน มีปุ่มหยุด อ่านอีกครั้ง และคัดลอกคำทำนาย) โดยใช้หลักการตีความ ความปลอดภัย และรูปแบบคำตอบย่อจาก skill นี้ ถ้าผู้ใช้ไม่อนุญาตหรือใช้ไม่ได้ หน้าจะกลับไปเป็นแบบคัดลอกผลไปวางในแชท

### หน้าคำถามมีช่องบริบท
หน้าตั้งจิตมีชิปเลือกสถานะตามหมวด (ความรัก: สถานะความสัมพันธ์ · เจาะเรื่อง: สถานะงาน/การเรียน) และช่องบริบทเพิ่มเติม (สเปรดเลือกทาง A/B จะขอให้ระบุตัวเลือก) ข้อมูลนี้ออกมาในบรรทัด `บริบท:` ของผลการจั่ว — ส่งบริบทที่ได้จาก intake ไปล่วงหน้าด้วย `ctx=` หรือ `--ctx` เพื่อไม่ให้ผู้ใช้ต้องพิมพ์ซ้ำ

### วิธีส่งหน้าให้ผู้ใช้ (เลือกตามสภาพแวดล้อม)
- **มีเครื่องมือเผยแพร่หน้าเว็บ/Artifact/Canvas:** เผยแพร่ไฟล์นี้ แล้วให้ลิงก์พร้อมพารามิเตอร์
- **มี browser pane หรือเครื่องมือเปิดไฟล์:** เปิดไฟล์ให้ผู้ใช้ (บางระบบเปิด `file://` แบบ snapshot ซึ่งอ่านพารามิเตอร์ใน URL ไม่ได้ — ให้ใช้ local server เช่น `python3 -m http.server --directory <skill>/assets` แทน)
- **ผู้ใช้อยู่บนเครื่องตัวเอง:** บอก path ของไฟล์ให้ดับเบิลคลิกเปิด ถ้าพารามิเตอร์ไม่ติด ผู้ใช้กรอกคำถาม/สเปรดในหน้าแรกเองได้

### พารามิเตอร์ใน URL (ไม่บังคับ — ช่วยกรอกหน้าแรกให้)
| พารามิเตอร์ | ความหมาย | ตัวอย่าง |
|---|---|---|
| `q` | คำถามที่เกลาแล้ว (URL-encode) | `q=แนวโน้มความรัก%203%20เดือน` |
| `spread` | id สเปรดจาก spreads.md — ใส่แล้วหน้าเว็บจะข้ามหน้าเลือกหมวด/แบบ ไปที่หน้าคำถามเลย (ไม่ใส่ = ผู้ใช้เริ่มจากเลือกหมวดเอง) | `spread=celtic-cross` |
| `rev` | `1` ใช้ไพ่กลับหัว (ค่าเริ่มต้น), `0` ไม่ใช้ | `rev=0` |
| `ctx` | บริบทที่ผู้ใช้เล่าแล้ว กรอกลงช่องบริบทให้ล่วงหน้า | `ctx=คุยกันมา%202%20เดือน` |
| `ret` | token สำหรับส่งผลกลับ ใส่ให้อัตโนมัติโดย `table_server.py` เท่านั้น | (ไม่ต้องใส่เอง) |
| `n` + `labels` | สเปรดที่ออกแบบเอง: จำนวนใบ + ชื่อตำแหน่งคั่นด้วย `\|` | `n=3&labels=เขาคิด\|เขารู้สึก\|เขาจะทำ` |

**ห้ามใส่ข้อมูลส่วนตัวที่อ่อนไหวใน `q`** (ชื่อจริง เบอร์ ฯลฯ) เพราะ URL อาจถูกบันทึกไว้ ใช้คำถามแบบทั่วไป แล้วให้ผู้ใช้เติมรายละเอียดในหน้าเองถ้าต้องการ

### อ่านผลที่ผู้ใช้ส่งกลับ
ข้อความขึ้นต้นด้วย "🔮 ผลการจั่วไพ่จากโต๊ะไพ่ทาโรต์" มีบรรทัด `คำถาม`, `สเปรด`, `ไพ่กลับหัว`, `พิธี` (ทุกขั้นที่ผู้ใช้ทำ) และรายการ `ลำดับ. ตำแหน่ง — ไพ่ (ชื่อไทย) · หัวตั้ง/กลับหัว` ตามด้วยไพ่กระเด็น/ไพ่ก้นสำรับ (ถ้ามี)
- ตีความตามข้อความนี้ทันที ไม่ต้องจั่วใหม่
- จะเอ่ยถึงพิธีที่ผู้ใช้ทำในคำทำนายก็ได้ ("คุณสับ riffle 4 รอบ ตัด 3 กอง...") ช่วยให้รู้สึกเป็นของเขาเอง
- ถ้าข้อความดูถูกแก้ไขหรือไม่ครบ (ไพ่ซ้ำ จำนวนไม่ตรงสเปรด) ให้ถามผู้ใช้ก่อนอ่าน

## โหมด A — ไพ่จริง

บอกขั้นตอนสั้น ๆ แล้วให้ผู้ใช้ทำตามจังหวะตัวเอง:

1. **ตั้งจิต:** หายใจลึก ๆ 2–3 ครั้ง นึกถึงคำถาม (บอกคำถามที่เกลาแล้วให้เขาอีกครั้ง)
2. **สับ:** สับวิธีไหนก็ได้ นานเท่าไหร่ก็ได้ หยุดเมื่อรู้สึกว่า "พอ" — ถ้าอยากให้มีไพ่กลับหัว ให้หมุนไพ่บางส่วนกลับด้านระหว่างสับ หรือกองไพ่บนโต๊ะแล้ววนมือ (wash)
3. **ไพ่กระเด็น (Jumper):** ถ้ามีไพ่หล่นหรือกระเด็นออกมา เก็บไว้ข้าง ๆ แล้วบอกมาด้วย จะอ่านเป็นข้อความเสริม
4. **ตัด:** ใช้มือซ้าย (หรือมือที่ถนัดน้อยกว่า) ตัดเป็นกี่กองก็ได้ แล้วรวมกลับในลำดับที่ต้องการ
5. **จั่ว:** จั่วจากด้านบนทีละใบ หรือแผ่ไพ่แล้วเลือกใบที่ดึงดูด — ตามจำนวนใบของสเปรด
6. **วาง:** วางตามลำดับตำแหน่ง (agent บอกตำแหน่งให้) แล้วแจ้งชื่อไพ่ + หัวตั้ง/กลับหัว หรือถ่ายรูปส่งมา

ถ้าผู้ใช้ส่งรูป: อ่านชื่อไพ่และทิศทางจากรูป ใบไหนไม่แน่ใจให้ถามยืนยัน — ทิศทางให้ยึดมุมมองของผู้ใช้ที่นั่งหน้าไพ่

## โหมด B — สำรับเสมือนจริง (`scripts/deck.py`)

สคริปต์เก็บสถานะสำรับไว้ในไฟล์ ทุกคำสั่งเปลี่ยนสำรับจริง ๆ — ผลจึงขึ้นกับสิ่งที่ผู้ใช้เลือก

### กติกาความยุติธรรม (สำคัญ)
- **agent ห้ามแอบดูลำดับไพ่** ห้ามเปิดไฟล์สถานะ ห้ามเลือกตำแหน่งแทนผู้ใช้ คำสั่ง `shuffle`/`cut`/`fan` จะไม่แสดงหน้าไพ่อยู่แล้ว
- ทุกตัวเลือก (วิธีสับ จำนวนรอบ จุดตัด จำนวนกอง ลำดับกอง ตำแหน่งที่จั่ว) มาจากผู้ใช้ ถ้าผู้ใช้บอก "ตามใจ" ค่อยใช้ค่าสุ่มของสคริปต์ (ไม่ส่งตัวเลือกนั้น)
- ผู้ใช้สับซ้ำ ตัดซ้ำ หรือเริ่มสำรับใหม่ได้ทุกเมื่อ **ก่อน** จั่ว — หลังจั่วแล้ว ห้ามจั่วใหม่เพื่อคำถามเดิม

### ขั้นตอน

**1. เปิดสำรับ** (บอกผู้ใช้: "หยิบสำรับขึ้นมาแล้วนะคะ")
```bash
python3 scripts/deck.py new                    # สำรับที่ผ่านการใช้มาแล้ว (ลำดับ/ทิศคละ)
python3 scripts/deck.py new --fresh            # สำรับใหม่แกะกล่อง เรียงลำดับ ตั้งหัวทั้งหมด
python3 scripts/deck.py new --no-reversals     # ไม่ใช้ไพ่กลับหัว
```

**2. ให้ผู้ใช้เลือกวิธีสับและจำนวนรอบ** — ถาม:
> "จะสับแบบไหนดีคะ: (1) Riffle ผ่าครึ่งแล้วสลับเข้ากัน (2) Overhand ดึงทีละกำ (3) Wash กองบนโต๊ะแล้ววนมือ — ทำให้ไพ่กลับหัวได้ (4) Pile แบ่งกองแล้วรวม — กี่รอบก็ได้ บอกว่า 'พอ' เมื่อรู้สึกว่าใช่"

```bash
python3 scripts/deck.py shuffle --method riffle --times 3
python3 scripts/deck.py shuffle --method wash --times 1
python3 scripts/deck.py shuffle --method pile --piles 4
```
- หลังสับแต่ละครั้ง บอกผู้ใช้สั้น ๆ ว่าทำอะไรไป (เช่น "สับแบบ riffle 3 รอบแล้ว") แล้วถามว่าจะสับต่อหรือพอ
- ถ้าผลมี `jumpers` แจ้งผู้ใช้ว่ามีไพ่กระเด็นออกมา และถามว่าจะอ่านเป็นข้อความเสริมหรือใส่คืน (`deck.py return-jumpers`)

**3. ให้ผู้ใช้ตัดไพ่** — ถาม:
> "ตัดไพ่กี่กองดีคะ (1–5) ตัดตรงไหน (เช่น ประมาณกลาง ๆ, ค่อนบน, หรือใบที่เท่าไหร่) และอยากรวมกองกลับลำดับไหน"

```bash
python3 scripts/deck.py cut --at 40                       # ตัดครั้งเดียว ที่ใบที่ 40
python3 scripts/deck.py cut --at middle                   # top / upper / middle / lower / bottom ก็ได้
python3 scripts/deck.py cut --piles 3 --order 2,3,1       # 3 กอง จุดตัดสุ่ม รวมกลับตามลำดับ 2,3,1
python3 scripts/deck.py cut --points 20,55 --order 3,1,2  # กำหนดจุดตัดเอง
python3 scripts/deck.py cut --piles 3 --order 3,2,1 --turn 2   # หมุนกองที่ 2 กลับหัว
```

**4. ให้ผู้ใช้จั่ว** — แผ่ไพ่ก่อน:
```bash
python3 scripts/deck.py fan
```
บอกผู้ใช้: "แผ่ไพ่ 78 ใบเรียงหน้าคว่ำแล้วค่ะ (ตำแหน่ง 1–78 จากซ้ายไปขวา) เลือก N ตำแหน่งที่รู้สึกดึงดูด หรือจะให้จั่วจากบนสุด/ล่างสุดก็ได้"

```bash
python3 scripts/deck.py draw --pick 7,33,61 --spread three-card   # ผู้ใช้เลือกตำแหน่งเอง
python3 scripts/deck.py draw --top 10 --spread celtic-cross       # จั่วจากบนสุด
python3 scripts/deck.py draw --bottom 1                           # จั่วใบล่างสุด
```
- ลำดับเลขที่ผู้ใช้เลือก = ลำดับตำแหน่งในสเปรด (เลขแรก → ตำแหน่ง 1)
- ถ้าผู้ใช้เลือกไม่ครบหรือเลือกซ้ำ ให้ขอเพิ่ม/เปลี่ยน
- **เปิดทีละใบได้** ถ้าผู้ใช้อยากลุ้น: จั่วทีละใบด้วย `--pick` ตำแหน่งเดียวต่อครั้ง (ตำแหน่งจะขยับหลังจั่ว ให้ `fan` ใหม่) แล้วอ่านทีละตำแหน่ง

**5. เสริม**
```bash
python3 scripts/deck.py bottom          # ดูไพ่ก้นสำรับ (รากลึกของเรื่อง) — เปิดเมื่อผู้ใช้ขอ
python3 scripts/deck.py status          # ประวัติการสับ/ตัด + จำนวนใบที่เหลือ (ไม่เปิดหน้าไพ่)
python3 scripts/deck.py draw --pick 12  # Clarifier ใบเพิ่มเติม จากสำรับเดิม
```

**จบการอ่าน:** เริ่มคำถามใหม่ด้วย `deck.py new` เสมอ (คืนไพ่ทุกใบเข้าสำรับ)

ไฟล์สถานะอยู่ที่ temp ของเครื่อง (`--state <path>` เพื่อเปลี่ยน) — ถ้ามีหลายผู้ใช้/หลายเซสชันพร้อมกัน ให้ใช้ไฟล์สถานะแยกกัน

## โหมด C — เลือกเลข (ไม่มีเครื่องมือรันโค้ด)

1. ให้ผู้ใช้ตั้งจิตถึงคำถาม
2. ให้ผู้ใช้พิมพ์เลข 1–78 ตามจำนวนใบ ไม่ซ้ำกัน (ไม่ต้องคิด ใช้เลขแรกที่ผุดขึ้นมา)
3. ถ้าใช้ไพ่กลับหัว: ให้ผู้ใช้บอกทิศของแต่ละใบด้วย "ตั้ง" หรือ "กลับ" ตามความรู้สึก หรือพิมพ์เลขโดดอีกหนึ่งตัวต่อใบ (คู่ = หัวตั้ง, คี่ = กลับหัว)
4. แปลงเลขด้วยตาราง "ลำดับไพ่ 1–78" ใน `techniques.md` ข้อ 11

แจ้งผู้ใช้ตรง ๆ ว่าโหมดนี้ใช้ตารางลำดับไพ่แบบคงที่ ถ้าอยากได้การสับจริงให้ใช้โหมด A หรือ B
